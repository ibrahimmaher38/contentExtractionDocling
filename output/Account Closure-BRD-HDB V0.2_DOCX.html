Activity CS01-Branch Customer Service-Maker

Item

Description

Activity IDCS01
Alias nameInitiation Account Closure Request
User Role / ActorMakers [Customer Services]
Task Due dateInitial value “WILL BE SET BY HDB” in order to calculate the task progress due time
PreconditionsThe user is authorized & successfully logged in the system
Main flow – Initiate new request
  • The user will be able to initiate new request for Account Closure.
  • The user will retrieve the customer data by CIF/NID then the workflow system will integrate with core banking to retrieve all the existing data for customer.
  • The user will be able to attach the required documents as described in the form specification.
  • The user has to upload the Account Closure form as an attachment in case there is no integration with tap devices.
  • the customer must have previous CIF/Account number has been created on core banking system, The system should validate it and don’t proceed to close the account if there is no CIF/Account number for customer.
  • The user will be able to write comment. (If there is any).
Alternative flow – Update returned request
  • The user will be able to modify returned request based on the comments and submit it again for his checker.
  • The system will validate the request data as mentioned above in the Main flow – Initiate new request process “as if the user is resetting the whole transaction “.
  • The user will be able to fill in the user comment with reason. (If there is any).
Alternative flow – TerminateThe user will be able to terminate the request before submit it.

Activity CS03-Branch Customer Service-Checker

Item

Description

Activity IDCS03
Alias nameApprove Account Closure Request
User Role / ActorCheckers [Branch customer services]
Task Due dateInitial value “WILL BE SET BY HDB” in order to calculate the task progress due time
Preconditions
  • The user is authorized & successfully logged in the system.
  • The task will proceed from maker to checker in case of: -
  • The case is initiated by maker and submit.
  • The case has some modifications(amendment) and returned to maker for correction and submit it again.
Main flow Acceptance Criteria – Approve maker action
  • the user will be able to view the initiated request from makers (Checker of branch customer services) as read only data.
  • the user will be able to view the added request attachments.
  • the user will be able to view the requested comments history (user – comment –date).
  • the user will be able to add comments.
  • the user will be informed with any validation errors.
Alternative flow – return request to maker
  • The user will be informed with any validation errors.
  • The user will be able to view the initiated request by the makers within the same number of branch customer services.
  • The user will be able to view the request detailed information.
  • The user will be able to view & browse attachments.
  • The user will able to return the request to maker and add comments to the request.
  • The system will complete the request successfully.

Assumptions and Constraints

Account Closure Process applied as a for any customer wants to close his account on the following assumptions:

  • The authorized users can use searching capabilities in the BPM system for the completed tasks and / or completed process within the user’s assigned branch and view the process instance data and its attachments.
  • The authorized Central unit users can use searching capabilities in the BPM system for the completed tasks and / or completed process for all transactions on the systems produced from all branches and sectors and view the process instance data and its attachments.
  • Any performance report can be generated from BPM system as long as the data is available in our system.
  • Any searching query can be defined from the BPM system as long as the metadata of this query is available on the system.
  • All interfaces will be in both Arabic and English languages.
